# Focused Interface Storytelling Video Production Skill

## Mission
Extract the repeatable relationship between composition, movement, timing, transition, emphasis, information and sound. Produce an original brand adaptation that preserves the supplied script and can be implemented without reopening the reference. Deliver a storyboard when requested; a rendered movie is a separate production stage.

## Input and evidence workflow
1. Establish reference access, script, brand assets, output surface and expected deliverables. Use explicit user choices; infer routine defaults and label them. Preserve personalization tokens.
2. Inspect media metadata, rotation, actual picture area, variable frame rate, audio start offset and capture artifacts. Distinguish file duration from the complete original film.
3. Review the entire temporal span at a coarse interval before defining shots. Inspect every meaningful state more densely, including transition start/middle/end. Record evidence timestamps and uncertainty. If playback or listening is unavailable, say exactly which evidence was inspected.
4. Separate observed facts, inferred methods and authored adaptation parameters. Never report recommended BPM, lens, easing or timing as measured fact.
5. Run the fourteen passes: macro structure; state ledger; composition; camera; motion; UI; typography; color/light; depth; transitions; rhythm; audio; presenter; production routing. Use “not present” or “unverified” rather than inventing missing evidence.
6. Build two distinct timelines: a reference state ledger and an adaptation keyed to the supplied narration. Do not replace a 2-minute script with a 30-second reference duration.
7. Save the full script separately. Scene narration concatenated in order must equal the script after whitespace normalization. Timing begins as an estimate; lock actual narration before a final animation build.
8. Produce MASTER VIDEO PRODUCTION BLUEPRINT in this order: Video DNA; Style Skill; Timeline Overview; Storyboard; Frame Compositions; Higgsfield Shots; HyperFrames Scenes; Transitions; Presenter Compositing; Audio Plan; Asset List; Production Order; Final Assembly Timeline; QC. Include creative rules to preserve and reference-specific things not to copy.
9. Supply machine-readable scene/layer/beat/asset/transition data and a human-reviewable HTML page. The page must identify placeholders and the difference between schematic preview and final animation.
10. Validate temporal coverage, scene IDs, personalization, Unicode, text fit, reverse seeking and final held frame. Report remaining media/audio/offer verification needs precisely.

## Visual Philosophy
A sequence of understandable changes is more valuable than decorative motion. Move from a concise phrase to a focused interaction, demonstrate a result, then clear the frame for the benefit. This skill's default style is high-key, front-on, soft-depth UI; adapt those defaults when contrary reference evidence exists.

## Creative Principles
- One primary reading task per frame.
- Preserve a brand/status anchor during busy task sequences.
- Preserve selected-object identity when moving from context to detail.
- Tie changes to the meaning of narration, not arbitrary periodic cuts.
- Leave the resolved state visible long enough to understand.
- A reference ending that was not captured is unknown, not a blank to fill with claimed observations.
- Hold the user's claims as supplied copy; don't add unsupported metrics, endorsements or offer terms.

## Composition System
Use a 5% safe margin. Author normalized boxes and a declared base canvas. Centered type can occupy 45–75% width; demonstrations can occupy 55–80%. Those are starting ranges, not fixed measurements of every reference. Use 2–3 text hierarchy levels and about 2–9 words of hero copy. Keep incidental UI subordinate. Re-layout a 4:3 carousel and 9:16 version explicitly instead of cropping important controls from a 16:9 film.

## Cinematography
Distinguish digital crop/scale from a physical camera. Do not invent lens or depth-of-field metadata for flat UI. For real/generated people, specify camera position, approximate focal length, travel distance, focal subject, start/end composition and light direction. Each generation prompt describes one continuous shot. Match people, clothes and location between related shots through reference assets when supported.

## Motion Language
Default entry: y24–60px, opacity 0→1, 400–650ms, outCubic. Default reframe: 450–700ms, inOutCubic. Stagger ordered elements by 60–100ms, with no more than 900ms total entrance. Keep readable states sharp. Restrict overshoot to a chosen tactile beat; do not bounce every headline. Specify numeric properties and units, initial state, proof state, final state, and final hold. These are production defaults to tune against evidence.

## Typography
Use verified brand font files locally; bundle their license. Preserve multilingual Unicode and test glyph coverage. Large text usually 76–104px at 1080p; functional UI text at least 30–36px when the viewer must read it. Use masks for word/line entrances; don't stretch text as a card expands. Long personalized names need a tested alternate line break or scale floor, not silent clipping.

## UI Animation System
Use real, approved screens or clearly labeled reconstructed examples. Avoid fake numerical claims. Prefer simplified essential states over a complete unreadable dashboard. Show selected language, action and resulting state distinctly. A QR design is a placeholder until encoded with an approved URL and tested. Never generate essential UI text in a video model. Keep decorative waveforms deterministic and clearly illustrative unless derived from actual audio.

## Presenter Treatment
Inspect whether a presenter is present at all. A character/avatar status badge is not a human presenter. Do not introduce a presenter by default. If requested, record one consistent plate, key/remove background only as needed, and define overlay box, safe region and occlusion rules. Maintain eye line and lighting; avoid covering controls or translated captions.

## Color System
Choose exact brand tokens after inspection. For Exbabel's current source: primary #394DFE, ink #0B1220, near-white #FCFCFD, pale cyan #D6F5FF, pale lavender #EAD6FF. Keep muted UI text sufficiently dark. Reference-derived palettes must be labeled estimates unless sampled/calibrated.

## Lighting System
UI depth comes from diffuse shadow, controlled edge contrast and a light background. Human inserts use a soft window/key from one side, restrained fill, natural skin and no dramatic color cast. Do not add grain, bloom, lens flare or chromatic aberration merely to look expensive.

## Transition Library
Specify each transition as an object with ID, duration, source/destination, transform channels, ease, masks, overlap and readable hold.
- Semantic replacement: fixed text alignment, masked 24–30px y travel.
- Selected-row expansion: same surface grows; surrounding context fades.
- Vertical stream: content exits upward and the next panel follows.
- Detail push: target coordinates determine translation, then scale to a useful action.
- Shared-anchor reframe: anchor persists; content changes beneath it.
- Payoff reset: complex surface leaves, one short outcome remains.
A true shared-object transition must reuse one object or a mathematically matched seam; calling a crossfade a morph is inaccurate.

## Editing Rhythm
Count semantic states separately from actual cuts. Calculate mean/median only against the stated ledger. Preserve fast 300–700ms transitions inside longer narration scenes rather than rushing every shot to match a shorter reference. Plan sub-beats roughly every 2–4 seconds where the script warrants change, with longer benefit/CTA holds. Narration recording supersedes estimated WPM.

## Sound Design
Analyze actual audio separately; if not auditioned, state that limitation and offer a proposed plan. Sample peak/dBFS is not LUFS or true peak. Use a licensed bed, restrained UI cues and dialogue ducking. Record VO before locking timings. Keep translatable captions separate from narration subtitles. All sound cue positions must be explicit and adjustable after VO alignment.

## Higgsfield Rules
Route people, environments, realistic physical action and cinematic footage to H where helpful. Default pure UI scenes to HF; zero H shots is valid. For each H shot provide Subject, Environment, Composition, Camera, Lens, Camera Movement, Lighting, Depth of Field, Motion, Performance, Color Grade, Texture, Duration, Start Frame, End Frame and Negative Instructions. Keep text/logo/screens blank for deterministic overlays. Describe start/end handles; trim generated material to the edit. Do not claim footage has been generated when only prompts exist.

## HyperFrames Rules
Read installed HyperFrames core and anime.js adapter contracts before implementation. Use the user's selected runtime. The known v4 integration:
- createTimeline({autoplay:false}); add(target, parameters, positionMs).
- v4 uses ease, not v3 easing; the anime global is a namespace.
- Register the timeline in window.__hfAnime; no v4 auto-discovery.
- Construct synchronously; finite loops; no random/time/input-dependent render state.
- JSON times are integer milliseconds; HTML data-start/data-duration are seconds.
- Root declares data-composition-id, width, height and static duration before runtime compilation; standalone root is not inside template.
- Use class clip for timed scenes; animate inner wrappers. HyperFrames owns clip visibility and media time.
- Never add video time attributes to both a video and its timed plain ancestor.
- An external HTML review player may own a playback clock, but do not import that clock into the render composition.
- Precompile JSON to HTML and load local assets; no render-time fetch.
- Use end-exclusive clip ranges; verify duration minus one frame, not a blank at exact duration.
- Pin package versions and validate the actual installed adapter. Do not claim renderer compatibility from a browser-only check.

Read references/anime-hyperframes.md for the executable integration boundary. The bundled assets/storyboard.schema.json is a data contract, not an animation engine.

## Compositing Rules
Give every layer a z order and normalized box. A generated plate never supplies final labels. Use a stable mask, foreground/midground/background assignments and explicit handles. Do not apply CSS distortions to text as part of a panel expansion; separate outer surface and inner content. Use FFmpeg/NLE for straightforward final assembly and audio when that is more reliable.

## Avoid
Copying reference brand names, exact marketing language, characters, proprietary illustrations, customer data or soundtrack; guessing a missing ending; calling a screenshot montage temporal analysis; floating every UI in 3D without evidence; unreadable full dashboards; uncontrolled live-site timers; placeholder QR codes disguised as working ones; claiming a schematic animatic is the finished film; deploying or publishing merely because local resources were requested.

## Quality-Control Checklist
- Source orientation, crop, duration, audio offset and artifact exclusions documented.
- All timeline segments covered; no silent gaps or unintended overlaps.
- Observations, estimates and recommendations visibly separate.
- Supplied VO preserved, including placeholders; no accidental rewriting.
- Every production unit has composition, layers, initial/final poses, beats, tool, assets and transition.
- Human shots maintain identity and no generative text is relied on.
- Font and translated glyphs render; personalized long names fit.
- Preview supports pause, seek and reduced-motion review; no required autoplay.
- Reverse seeking returns identical poses; every scene has a readable proof frame.
- Final frame holds rather than disappearing/resetting.
- Actual HyperFrames checks and rendered-frame checks recorded separately from browser tests.
- Missing audio/media and unverified commercial claims are reported as open production items.
